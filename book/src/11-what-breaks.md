# Chapter 11. What breaks

You and a friend are playing a strategy game in lockstep multiplayer against a computer opponent. Neither machine sends the other the state of the world. Each runs the full simulation itself, and only the players' orders travel over the network; as long as both machines start from the same state and apply the same orders on the same ticks, they stay identical. The opponent plans with Monte Carlo tree search, given a fixed slice of time to think before each decision.

Your friend's computer is faster. In the same slice of time it plays out more futures, and on one decision the move it has visited most is a different move from the one your machine settled on. For a few seconds nothing looks wrong. The two worlds have already split: on one screen the enemy's cavalry turns north, on the other it holds. Then the machines compare checksums, the numbers disagree, and the match stops with a desync error that neither of you can do anything about.

The dataset's record for the technique lists this exact failure: time-budgeted search returns different moves on different hardware, which breaks replays and lockstep multiplayer unless budgets are counted in iterations with seeded randomness. The fix is cheap once you know it. Count playouts instead of milliseconds, seed the random numbers, and every machine computes the same move. The record therefore marks the technique as mitigable.{{assert:field.monte-carlo-tree-search.determinism_impact == mitigable}}

This chapter is about the ways AI techniques fail inside simulation games, and the reason so many of them fail in the same few places. Simulation games demand things that most software does not: the same inputs must produce the same world, every output a player sees becomes evidence for how the system works, and a single purchase has to pay for hundreds of hours of play.

## The same inputs, the same world

[[factorio|Factorio]]'s record notes that its item movement is discrete and deterministic, belts carrying a fixed number of items per second on two lanes, and that this is what lets its lockstep multiplayer simulate identical worlds on every machine. The same property supports a long list of things players never think about. A replay is a recording of inputs, played back through the same rules. A bug report from a player can be reproduced by loading the save and replaying the inputs. A leaderboard can be trusted because a submitted run can be re-simulated. A save file loads into the same world that was saved.

Each technique in the dataset records its effect on that property. Chapter 6 counted the techniques that can run during play: {{stat:n_technique_runtime}} of them, of which {{stat:n_technique_runtime_breaks}} break reproducibility outright, {{stat:n_technique_runtime_mitigable}} can be made reproducible, and {{stat:n_technique_runtime_preserves}} leave it intact.{{assert:n_technique_runtime_breaks < n_technique_runtime_mitigable}} The ones that break it share a cause. A frame-generating world model, a language-model game master, a society of language agents, a realtime voice model: each samples its output, the sample depends on hardware and timing and the model's version, and its output decides what happens next.{{assert:field.genie-world-models.determinism_impact == breaks}}{{assert:field.llm-game-master.determinism_impact == breaks}}{{assert:field.llm-agent-societies.determinism_impact == breaks}}{{assert:field.realtime-voice-models.determinism_impact == breaks}}

A mitigable technique can be pinned down by seeding its randomness, storing its output, or bounding its computation by work instead of time. [[infinite-craft|Infinite Craft]] stores the output. When a player combines two elements for the first time, the game asks a language model for the result, then writes the answer to a database; every later player who combines the same pair gets the stored answer. The record describes the effect as a stochastic model turned into a growing deterministic rule table, with the cost bounded by the number of distinct questions.{{assert:field.llm-rule-adjudication.determinism_impact == mitigable}} A small model running on the player's own GPU can be seeded, which is why the record for on-device language models marks them mitigable too.{{assert:field.on-device-language-models.determinism_impact == mitigable}}

The techniques that leave reproducibility intact mostly never touch the simulation. Neural upscaling and frame generation work on the rendered image after the simulation has decided everything, which is part of why they became the one learned technique that is a norm in games (chapter 7).{{assert:field.neural-rendering-shaders.determinism_impact == preserves}}{{assert:field.neural-rendering-shaders.maturity == shipped-mainstream}} The others are deterministic algorithms run at play time, such as wave function collapse, which [[townscaper|Townscaper]] runs in real time to work out how the houses you place fit together.{{assert:field.wave-function-collapse.determinism_impact == preserves}} A deterministic algorithm can generate as much as it likes; given the same seed and the same clicks, it generates the same town.

The bets in chapter 10 inherit these properties from the techniques they apply. Of the {{stat:n_predictions}} opportunities, {{stat:n_opportunity_applies_breaking}} rely on at least one technique that breaks reproducibility outright.{{assert:n_opportunity_applies_breaking < n_predictions}} Each of them needs a plan for what the log records, or it gives up replays and multiplayer.

## Contradiction

A gap in a simulation game is survivable. A contradiction is worse, because players use what the game shows them to build their model of how it works. A colonist who mourns a friend who is alive, a road that was there a moment ago, a price that changes when nothing changed: each teaches the player something false.

Consistency is listed as a risk on {{stat:n_technique_risk_consistency}} of the {{count:technique}} techniques in the dataset,{{assert:n_technique_risk_consistency >= 15}} and the evidence for it is specific. On 76,369 state transitions from 31 text games, GPT-4 predicted the full next state correctly at most 59.9 percent of the time, and at most 49.7 percent for changes the environment caused on its own [@src-wang-2024-text-world-simulators]. A diffusion world model trained on 87 hours of Counter-Strike play lets the player jump repeatedly in mid-air, which the real game forbids [@src-alonso-2024-diamond]. In a 28-player study with five language-model characters, players reported characters forgetting their own earlier statements in 10 percent of reports [@src-peng-2024-player-driven-emergence], and surveyed language-model game masters invent quests that do not exist in the game [@src-gallotta-2024-llms-games-survey].

The pattern points to where a language model can safely sit. Asked to predict what the simulation will do, a model gets it wrong often enough to mislead. Asked to describe what the simulation did, from a log of events the simulation computed, it has the right answer in front of it. The record for language-model explanation of state draws the same line: explanations of dynamics should be computed by the simulation and only narrated by the model, and because the explanation layer reads state without writing it, the simulation stays deterministic.{{assert:field.llm-explanation-of-state.determinism_impact == preserves}}

## Opaque replacements

Deep simulations already struggle to be understood. Chapter 5 showed that the mechanics rated most emergent are rated hardest to read, and designers answered with a whole family of mechanics that own no simulation state and exist to explain the rest: overlays, inspectors, tooltips, chronicles. A learned component can undo that work. A policy trained to run a city's traffic or a rival's pricing may play well and still offer no reason for what it does, which moves the mechanic it replaced down the legibility scale.

Legibility is listed as a risk on {{stat:n_technique_risk_legibility}} techniques, including Monte Carlo tree search, whose choices come from thousands of playouts no player will see, and mean-field games, which replace a crowd of individual decisions with one representative agent responding to the population as a whole, so there is no individual decision to inspect.{{assert:n_technique_risk_legibility >= 5}} The remedy the dataset proposes is the same for every case: each learned component that affects state needs an explanation path, and the cheapest one is a log of what it decided and on what inputs.

## The bill

Most simulation games are sold once and played for a very long time. A feature that costs money every time a model is called turns each player-hour into a running cost. Compute cost is listed as a risk on {{stat:n_technique_risk_compute_cost}} techniques, second only to controllability.{{assert:n_technique_risk_compute_cost >= 20}}

The numbers behind that risk vary by orders of magnitude. The 25-agent Smallville simulation behind the original generative agents paper cost thousands of dollars in model credits and took several days of wall-clock time [@src-park-2023-generative-agents]; replaying cached plans cut a later version's token use to 42.7 percent of the baseline for the same 25-agent town [@src-yu-2024-affordable-generative-agents]. When Google opened its Genie 3 world model to subscribers in January 2026, each generated world was limited to 60 seconds, a limit DeepMind attributed to limited compute [@src-techcrunch-2026-project-genie]. At the other end, pruning, distillation, and 4-bit quantization fit a 2-billion-parameter character model into about 1.5 GB of video memory beside the game's rendering [@src-sreenivas-2024-minitron; @src-nvidia-2025-ace-companions], although NVIDIA's in-game inference SDK still asks for an RTX 30-series card or newer with at least 8 GB [@src-nvidia-2026-nvigi-core]. Local inference moves the cost onto the player's hardware and off the developer's bill, which is the case the local-first opportunity in chapter 10 makes.

## Steering and checking

The risk listed most often across all {{count:technique}} techniques is {{stat:top_technique_risk}}: the designer cannot reliably make the technique do what the design needs.{{assert:top_technique_risk == controllability}}{{assert:n_technique_risk_controllability > n_technique_risk_compute_cost}} It appears on {{stat:n_technique_risk_controllability}} of them. A language-model game master tends to accommodate requests a human game master would refuse [@src-gallotta-2024-llms-games-survey]. A world model accepts a prompt for weather or a new character mid-session and decides for itself what that looks like. A level generator produces something valid that no designer would have chosen.

Close behind is evaluation, listed on {{stat:n_technique_risk_evaluation}}: when a system can produce an unbounded variety of outputs, nobody can check them all.{{assert:n_technique_risk_evaluation >= 15}} Automated playtesting can check that generated content is valid and balanced; it says little about whether a generated event is any good. Human review does not scale to generated variety. This dataset faces the same problem with its own records and answers it with a verification queue: sampled, scored against anchors, and logged (chapter 13). Games will need something similar for what their generators produce.

## Trust, authorship, and safety

Players and the people who make games have their own reasons to distrust generated content, and chapter 7 covered how reception has gone. Two cases show what the risk looks like in operation. In 2021 AI Dungeon added a filter to block sexual content involving minors; it flagged innocent text as well, human moderators read flagged private stories, and players review-bombed the game [@src-wikipedia-ai-dungeon]. The SAG-AFTRA video game strike, which ran from July 2024 to July 2025, ended with contract terms requiring consent for AI voice replicas [@src-wikipedia-artificial-intelligence-in-video-games]. Steam's disclosure rules separate content generated before release from content generated during play, and ask developers of the second kind to describe their guardrails [@src-valve-2026-steamworks-content-survey].

These risks fall unevenly across the bets. Opportunities that help players understand a game or author more of it, such as explanation, modding by description, and orders given as intentions, replace no one's work and generate nothing a player did not ask for. Opportunities that replace authored writing, voices, or art carry the whole weight of the labor and trust questions.

## A log as the fix

One design answers several of these failures at once, and chapter 10 ranked it among the top bets. The event-sourced simulation runtime records every state change as an event with its inputs, its output, and its cause, including the changes a model decided. The log is the source of truth and the game state is a projection of it.{{assert:rank.opportunities-ranked.event-sourced-sim-runtime <= 5}}

Each failure above has a corresponding use of the log. A replay or a multiplayer client reads the logged output of a model call instead of calling the model again, so a technique that breaks reproducibility becomes reproducible after the fact; the opponent's move in the desynced match would have been decided once and sent to both machines as an event. A bug report includes the log, so the developer can step through what the model said. A why-query can cite the events that caused an outcome, and a branch preview can fork from any event. The record lists the precedents for the parts: [[dwarf-fortress|Dwarf Fortress]]'s legends, Factorio's deterministic replays, and [[eve-online|EVE Online]]'s persistent world.

The validation experiment is plain engineering. Wrap the model calls of an agent prototype in an event log, replay a hundred sessions, and check that the state is reconstructed byte for byte and that forked branches differ only after the fork point. Success is every replay reproducing, with the log adding less than 20 percent to the size of a save per hour of play. The prediction is that by the end of 2028 an engine, a middleware vendor, or an open-source project will ship an event-log replay layer designed for games with generative components, used by at least one title with 1,000 Steam reviews.{{assert:field.event-sourced-sim-runtime.falsifiable_signal.resolve_by == 2028-12-31}}

A second tool limits what a model can write in the first place. Constrained decoding masks every token that would take the output outside a schema or grammar, so a model asked for a game action can only produce an action the engine can execute, against targets that exist. A hosted structured-output mode reached 100 percent on a complex schema-following test, against under 40 percent for an earlier model without constraints [@src-openai-2024-structured-outputs]. Strict formats have a cost: they reduced models' reasoning accuracy compared with free-form answers, and stricter formats cost more [@src-tam-2024-let-me-speak-freely]. The record also states that no source documents constrained decoding in a specific shipped game; it is scored as research for games despite being routine elsewhere.{{assert:field.constrained-decoding.maturity == research}}

Together the two tools describe an architecture. The authoritative simulation stays symbolic and deterministic. Models propose changes in a typed format that a validator accepts or rejects, every accepted change is logged, and everything a player sees can be traced back to an entry in the log. The narrative engine behind Hidden Door works this way: it checks every story turn against its canon and rules before showing it [@src-hiddendoor-2026-homepage].

## Exercise: trace a failure

Pick an AI feature you have seen in a game, or one from chapter 10.

1. Write down what state it writes. If the answer is "none", say what it reads and what the player sees.
2. Decide whether a replay of the session would show the same output. If not, write what the log would have to record for it to do so.
3. Describe the first contradiction a player is likely to see, and how the player would find out that the game was wrong and not their understanding of it.
4. Estimate the cost per player-hour, and who pays it.

The exercise tends to sort features into two groups: those that can be fixed with a log and a schema, and those whose value depends on doing something no log can make repeatable. Whether the first group ships first is one of the questions the predictions in chapter 12 are set up to answer, starting on {{stat:first_prediction_resolves}}.
